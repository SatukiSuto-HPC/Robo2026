🔍 独自発見・特徴的指摘

他のモデルが見落とした重要な指摘。発見の多様性が評価の差を生む。

Claude 独自 DRV8825 電流スパイクリスク

左右モーターの STEP パルスを同時発行することで DRV8825 ドライバに電流スパイクが発生し、ESP32 の 3.3V ロジックラインがリセットするリスクを指摘。ハードウェア故障リスクまで追跡した唯一の指摘。

Claude 独自 begin() / start() の重複インターフェース

web_server.py に初期化メソッドが2種類存在し、一方が未使用のデッドコードになっている点を指摘。API設計の一貫性問題。

Claude 独自 points がUI未表示

API から d.points を受信しているのに index.html の画面に反映していない UI バグを発見。フロントエンドとバックエンドの齟齬。

Claude 独自 _normalize_angle_deg とサーボ制限の不一致

逆運動学の正規化が -180°〜+180° なのに対してサーボ制限バリデーションが 0°〜180° のみで、物理的に到達可能な位置が到達不可と判定される論理矛盾を発見。

Qwen 独自 ★最重要 index.html アップロード手順の欠落

README / HANDOVER のアップロード手順に index.html が記載されておらず、手順どおりに作業するとダッシュボードが必ず 500 Error になるドキュメントバグを単独発見。実害が最も大きい。

Qwen 独自 ★重要 PASSING_LINE の 2倍速暴走

execute_passing_line_step() のステップゲートが欠落しており、毎 update (0.5〜1ms) でモーターが駆動されて通常速度の約2倍で前進する安全上の問題を発見。

Qwen 独自 P制御の符号が Arduino 元版と逆

他のモデルが「P制御が呼ばれていない」に止まったのに対し、Qwen はさらに execute_tracking_speed() の補正符号自体が Arduino 元版と逆であり、接続してもラインから離れる正帰還になる点を指摘。

Qwen 独自 UART '1' がアーム実行中を中断

RPi から '1' を受信するとアーム再生中でも即座に TURN_LEFT 遷移し、シーケンス整合性が崩れる競合状態を発見。ステートマシンの設計バグ。

Qwen 独自 TURN_LEFT タイムアウト欠如

ラインを一度も検知しない限り永遠に旋回し続けるリスクを指摘。MAX_TURN_DURATION_MS の追加を提案した唯一のモデル。

Qwen 独自 無点数トリガーの無言通過

ティーチング点が0個の状態でマーカーを検知した場合、警告なしにそのまま前進し続ける誤動作を発見。play() の戻り値が無視されている問題。

Qwen 独自 attach_servos() の PWM 重複チャネル

SERVO_ON を連打すると既存の PWM を deinit せずに新規作成するため、重複チャネルが発生する可能性を指摘。

Gemini 独自 IK Elbow Down 計算バグ

else: t1_rad = alpha + beta が elbow_up と同一の計算になり、下肘姿勢の解が求まらない数学的バグを発見。修正コードも「常に alpha - beta」と明快に提示。

Gemini 独自 gc.collect() によるモーター脱調

1秒間隔のステータスポーリングごとに同期 GC が実行され、CPUが停止してステッピングモーターが脱調する問題を発見。MicroPython 固有の協調スケジューリング問題の深い理解。

Gemini 独自 os.listdir() のヒープ消費

ファイル存在確認に os.listdir() を使うとディレクトリ全体のファイル名リストが RAM 上に生成される問題を発見し、try-open パターンへの変更を提案。

OpenCode 独自 Wi-Fi セキュリティ問題

authmode=0 によるオープンネットワークを高優先度として指摘。他モデルは「authmode=0 は no-op」として低優先度に留めたのに対し、WPA2-PSK 設定の修正コードまで提示。

OpenCode 独自 MAX_TEACH_POINTS の定数分散

MAX_TEACH_POINTS = 32 が teaching.py にハードコードされており、config.py への一元管理を提案した唯一のモデル。保守性の観点。
